# Document Request Portal

ระบบขอเอกสารออนไลน์สำหรับงานทะเบียนของโรงเรียนและมหาวิทยาลัย
**ยื่นคำร้อง → ตรวจสอบข้อมูล → ติดตามสถานะ → แจ้งเมื่อเอกสารพร้อมรับ**

ไม่ต้องใช้ Node.js หรือขั้นตอน build ตัวเว็บเป็น HTML + JavaScript (ES modules) ล้วน เชื่อมต่อฐานข้อมูลผ่าน Supabase

## ฟีเจอร์

**นักเรียน/นักศึกษา** (ไม่ต้องสมัครสมาชิก)
- เลือกประเภทเอกสาร พร้อมดูค่าธรรมเนียม ระยะเวลา และเอกสารที่ต้องแนบ
- กรอกข้อมูลและแนบไฟล์ (PDF/JPG/PNG ไม่เกิน 5 MB, สูงสุด 5 ไฟล์)
- รับรหัสติดตาม และตรวจสถานะได้ด้วยรหัสติดตามคู่กับรหัสนักเรียน
- สลับภาษาไทย/อังกฤษได้ทันที

**เจ้าหน้าที่ทะเบียน** (ล็อกอิน)
- ดู กรอง และค้นหาคำร้อง
- เปิดไฟล์แนบ เปลี่ยนสถานะ และฝากข้อความถึงผู้ยื่น
- ประวัติการเปลี่ยนสถานะบันทึกอัตโนมัติ
- สมัครบัญชีใหม่ได้เองที่หน้า `#/register` โดยต้องใส่รหัสลงทะเบียนที่ผู้ดูแลระบบตั้งไว้

## เทคโนโลยี

| ด้าน | สิ่งที่ใช้ |
|---|---|
| ภาษา | HTML, CSS, JavaScript (ES modules), SQL (PostgreSQL / PL/pgSQL) |
| Framework | ไม่มี (vanilla JavaScript + hash router) |
| ไลบรารี | `@supabase/supabase-js` v2 (CDN), ฟอนต์ Sarabun (Google Fonts) |
| Backend | Supabase: PostgreSQL, Auth, Storage, Row Level Security, RPC |
| Hosting | Vercel (static) |
| Source control | GitHub |

## โครงสร้างโปรเจกต์

```
index.html              โครงหน้าเว็บ
css/styles.css          สไตล์ทั้งหมด
js/config.js            ค่าเชื่อมต่อ Supabase (URL + anon key)
js/app.js               router และแถบเมนู/ปุ่มสลับภาษา
js/i18n.js              ข้อความภาษาไทย/อังกฤษทั้งหมด
js/lib/supabase.js      Supabase client
js/lib/utils.js         ฟังก์ชันและค่าคงที่ที่ใช้ร่วมกัน
js/pages/home.js        #/          หน้าแรก
js/pages/request.js     #/request   ยื่นคำร้อง
js/pages/track.js       #/track     ติดตามสถานะ
js/pages/admin.js       #/admin     หลังบ้านเจ้าหน้าที่
js/pages/register.js    #/register  สมัครเจ้าหน้าที่ (ต้องมีรหัสลงทะเบียน)
supabase/schema.sql     ตาราง นโยบาย RLS ฟังก์ชัน RPC storage และข้อมูลตัวอย่าง
supabase/add_staff_registration.sql  แพตช์ระบบสมัครเจ้าหน้าที่ (สำหรับฐานข้อมูลที่รัน schema.sql ไปแล้ว)
vercel.json             HTTP security headers
```

## โครงสร้างข้อมูล

| ตาราง | หน้าที่ |
|---|---|
| `request_types` | ประเภทเอกสาร: ชื่อ คำอธิบาย ค่าธรรมเนียม จำนวนวันดำเนินการ เอกสารที่ต้องแนบ (มีคอลัมน์ `_th` สำหรับภาษาไทย) |
| `requests` | คำร้อง: ข้อมูลผู้ยื่น รหัสติดตาม สถานะ ข้อความจากเจ้าหน้าที่ |
| `attachments` | ข้อมูลไฟล์แนบ (ตัวไฟล์อยู่ใน Supabase Storage) |
| `status_history` | ประวัติการเปลี่ยนสถานะ (เขียนโดย database trigger) |
| `staff` | ผู้ใช้ที่ได้รับสิทธิ์เป็นเจ้าหน้าที่ |
| `staff_settings` | ค่าตั้งค่าลับ เช่น รหัสลงทะเบียนเจ้าหน้าที่ (เปิดอ่านได้จาก SQL Editor เท่านั้น) |
| `staff_register_attempts` | จำนวนครั้งที่กรอกรหัสลงทะเบียนผิดของแต่ละผู้ใช้ (ผิดครบ 5 ครั้งจะถูกล็อก) |

ฟังก์ชัน RPC: `submit_request`, `add_attachment`, `track_request` (ผู้ยื่นคำร้อง) และ `register_staff` (ผู้ใช้ที่ล็อกอินแล้ว)

### ค่าสถานะ

`submitted` → `reviewing` → `need_more_info` → `approved` → `processing` → `ready` → `completed` และ `rejected`, `cancelled`

## ข้อกำหนด (Requirements)

### Functional

| รหัส | ข้อกำหนด |
|---|---|
| FR-1 | เลือกประเภทเอกสารที่เปิดให้ขอ พร้อมแสดงค่าธรรมเนียม ระยะเวลา และเอกสารที่ต้องแนบ |
| FR-2 | กรอกชื่อ รหัสนักเรียน อีเมล เบอร์โทร วัตถุประสงค์ จำนวนฉบับ (1–20) และวิธีรับ (รับเอง/ไปรษณีย์) |
| FR-3 | แนบไฟล์ได้สูงสุด 5 ไฟล์ ชนิด PDF/JPG/PNG ไม่เกิน 5 MB ต่อไฟล์ |
| FR-4 | ได้รับรหัสติดตาม (`DR-XXXXXXXX`) หลังยื่นสำเร็จ |
| FR-5 | ดูสถานะ ข้อความจากเจ้าหน้าที่ และประวัติสถานะ โดยกรอกรหัสติดตามและรหัสนักเรียนให้ตรงกัน |
| FR-6 | เจ้าหน้าที่ล็อกอินและเห็นคำร้องล่าสุด 200 รายการ |
| FR-7 | กรองตามสถานะ และค้นหาด้วยรหัสติดตาม รหัสนักเรียน หรือชื่อ |
| FR-8 | เปิดดูรายละเอียดและดาวน์โหลดไฟล์แนบ |
| FR-9 | เปลี่ยนสถานะพร้อมฝากข้อความที่แสดงให้ผู้ยื่นเห็น |
| FR-10 | บันทึกประวัติสถานะอัตโนมัติทุกครั้งที่เปลี่ยนสถานะ |
| FR-11 | สมัครบัญชีเจ้าหน้าที่ด้วยอีเมล รหัสผ่าน และรหัสลงทะเบียน (ปิดรับสมัครได้โดยลบรหัสออกจากฐานข้อมูล) |

### Non-functional

| รหัส | ข้อกำหนด |
|---|---|
| NFR-1 | ใช้งานได้ทั้งมือถือและเดสก์ท็อป (responsive) |
| NFR-2 | เปิด Row Level Security ทุกตาราง ผู้ยื่นอ่านตาราง `requests` ตรง ๆ ไม่ได้ |
| NFR-3 | ไฟล์แนบเก็บแบบ private จำกัดชนิดและขนาด เจ้าหน้าที่เปิดผ่านลิงก์ชั่วคราวอายุ 2 นาที |
| NFR-4 | deploy ได้โดยไม่ต้อง build |
| NFR-5 | รองรับภาษาไทย/อังกฤษ สลับได้ทันที ค่าเริ่มต้นคือไทย |

## การติดตั้งและเปิดใช้งาน

คู่มือนี้พาตั้งแต่เริ่มต้นจนได้เว็บที่เปิดใช้งานจริง โดยใช้บริการฟรี 3 ตัว: **Supabase** (ฐานข้อมูล), **GitHub** (เก็บโค้ด) และ **Vercel** (เปิดเว็บ) ไม่ต้องติดตั้งโปรแกรมใด ๆ ลงเครื่อง (ใช้แค่เบราว์เซอร์ และโปรแกรมแก้ไขข้อความอย่าง VS Code หรือ Notepad)

### สิ่งที่ต้องมี

- บัญชี [Supabase](https://supabase.com), [GitHub](https://github.com) และ [Vercel](https://vercel.com) (สมัครด้วยบัญชี GitHub ได้)
- โฟลเดอร์โปรเจกต์ (แตกไฟล์ `document-request-portal.zip`)

### 1) สร้างโปรเจกต์ Supabase

1. เข้า Supabase → **New project**
2. ตั้งชื่อโปรเจกต์ ตั้ง Database Password (จดเก็บไว้) เลือก Region ใกล้ไทย เช่น Singapore → **Create new project** แล้วรอ 1–2 นาที

### 2) สร้างตารางและข้อมูลเริ่มต้น

1. เมนูซ้าย **SQL Editor** → **New query**
2. เปิดไฟล์ `supabase/schema.sql` คัดลอกทั้งไฟล์มาวาง → กด **Run**
3. ต้องขึ้นข้อความ **Success** (ถ้าเคยรันแล้วเกิด error ว่ามีอยู่แล้ว ให้ลบโปรเจกต์สร้างใหม่ หรือรันเฉพาะส่วนที่ขาด)

> ถ้าฐานข้อมูลของคุณรัน `schema.sql` เวอร์ชันเก่าไปแล้ว (ยังไม่มีระบบสมัครเจ้าหน้าที่) ให้รัน `supabase/add_staff_registration.sql` เพิ่มอีกไฟล์

### 3) ตั้งค่าการยืนยันอีเมล (เลือกอย่างใดอย่างหนึ่ง)

ไปที่ **Authentication → Sign In / Providers → Email**

- **ใช้อีเมลจริง:** เปิด **Confirm email** ไว้ แล้วทำข้อ 6 (URL Configuration) ให้ครบหลัง deploy
- **ทดสอบด้วยอีเมลสมมติ:** ปิด **Confirm email** แล้วกด Save สมัครแล้วใช้งานได้ทันที

### 4) ตั้งรหัสลงทะเบียนเจ้าหน้าที่

ที่ SQL Editor รันคำสั่งนี้ โดยเปลี่ยนรหัสเป็นของคุณเอง (อย่างน้อย 8 ตัวอักษร เดายาก และไม่ใช้ข้อความตัวอย่าง):

```sql
insert into staff_settings (key, value) values ('registration_code', 'รหัสของคุณ')
on conflict (key) do update set value = excluded.value;
```

- ปิดรับสมัครเจ้าหน้าที่: `delete from staff_settings where key = 'registration_code';`
- ผู้ใช้ที่กรอกรหัสผิดครบ 5 ครั้งจะถูกล็อก ปลดล็อกด้วย `delete from staff_register_attempts where user_id = '<USER UUID>';`

### 5) ใส่ค่าเชื่อมต่อในโค้ด

1. Supabase → **Project Settings → API** (หรือ **Data API / API Keys**)
2. คัดลอก **Project URL** และ **anon public key**
3. เปิด `js/config.js` แล้วแทนที่ค่า:

```js
export const SUPABASE_URL = "https://xxxxxxxx.supabase.co";
export const SUPABASE_ANON_KEY = "eyJ...";
```

> ใช้เฉพาะ **anon (public) key** เท่านั้น ห้ามใส่ `service_role` key ในโค้ดเด็ดขาด

### 6) อัปโหลดโค้ดขึ้น GitHub

1. GitHub → **New repository** ตั้งชื่อ เช่น `document-request-portal` → **Create repository**
2. กด **uploading an existing file** แล้วลากไฟล์และโฟลเดอร์ทั้งหมดในโปรเจกต์วาง (ต้องมี `index.html`, `css/`, `js/`, `supabase/`, `vercel.json`)
3. กด **Commit changes**

### 7) Deploy บน Vercel

1. Vercel → **Add New… → Project** → เลือก repo ที่สร้างไว้ → **Import**
2. **Framework Preset** เลือก **Other** ส่วนอื่นปล่อยค่าเริ่มต้น (ไม่ต้องมี build command)
3. กด **Deploy** รอสักครู่จะได้ลิงก์ เช่น `https://document-request-portal-xxxx.vercel.app`

### 8) ตั้ง URL ใน Supabase (จำเป็นถ้าเปิดยืนยันอีเมล)

Supabase → **Authentication → URL Configuration**

- **Site URL:** ใส่โดเมนจริงจาก Vercel (ไม่ใช่ตัวอย่าง `xxxx`)
- **Redirect URLs:** กด **Add URL** ใส่โดเมนเดียวกัน (ถ้ามี `/**` ต่อท้ายก็ได้) แล้ว Save

### 9) สร้างบัญชีเจ้าหน้าที่คนแรก

1. เปิดเว็บ → เมนู **เจ้าหน้าที่** → ลิงก์สมัคร (`#/register`)
2. กรอกชื่อ อีเมล รหัสผ่าน (อย่างน้อย 8 ตัว) และรหัสลงทะเบียนจากข้อ 4
3. ถ้าเปิดยืนยันอีเมล ให้กดลิงก์ในอีเมลก่อน แล้วล็อกอินที่หน้าเจ้าหน้าที่ ระบบจะให้กรอกรหัสลงทะเบียนอีกครั้งเพื่อเปิดใช้งานบัญชี

### 10) ทดสอบระบบ

1. หน้าแรก → **ยื่นคำร้อง** กรอกข้อมูลและแนบไฟล์ (PDF/JPG/PNG ไม่เกิน 5 MB) → จะได้รหัสติดตาม `DR-XXXXXXXX`
2. หน้า **ติดตามสถานะ** ใส่รหัสติดตามและรหัสนักเรียน
3. ล็อกอินเจ้าหน้าที่ → เปิดคำร้อง เปลี่ยนสถานะ ฝากข้อความ แล้วกลับไปตรวจที่หน้าติดตาม

### การอัปเดตโค้ดภายหลัง

แก้ไฟล์ แล้วอัปโหลดทับใน GitHub (**Add file → Upload files** → Commit) Vercel จะ deploy ใหม่เองภายใน 1 นาที จากนั้นกด Ctrl+F5 ที่หน้าเว็บ อย่าอัปโหลดทับ `js/config.js` ด้วยไฟล์ตัวอย่าง

### แก้ปัญหาที่พบบ่อย

| อาการ | วิธีแก้ |
|---|---|
| หน้าเว็บขึ้นว่ายังไม่ได้ตั้งค่า | ยังไม่ได้ใส่ URL / anon key ใน `js/config.js` หรือยังไม่ได้อัปโหลดไฟล์ที่แก้แล้ว |
| ลิงก์ยืนยันอีเมลเปิดไม่ได้ / ไปหน้าแปลก | Site URL / Redirect URLs ใน Supabase ไม่ตรงกับโดเมนจริง (ข้อ 8) |
| สมัครแล้วขึ้นว่าอีเมลยังไม่ยืนยัน | ยืนยันอีเมลก่อน หรือปิด Confirm email (ข้อ 3) |
| กรอกรหัสลงทะเบียนแล้วไม่ผ่าน | รหัสผิด ถูกล็อกหลังผิด 5 ครั้ง หรือยังไม่ได้ตั้งรหัส (ข้อ 4) |
| แนบไฟล์ไม่ได้ | ไฟล์ไม่ใช่ PDF/JPG/PNG หรือใหญ่เกิน 5 MB หรือไม่ได้รัน `schema.sql` ส่วน Storage |
| เจ้าหน้าที่ไม่เห็นคำร้อง | บัญชียังไม่อยู่ในตาราง `staff` ตรวจที่ Table Editor |
| แก้โค้ดแล้วหน้าเว็บไม่เปลี่ยน | รอ Vercel deploy เสร็จ แล้วกด Ctrl+F5 |

## ข้อจำกัดที่ทราบ

- ยังไม่มีแจ้งเตือนทางอีเมล/LINE เมื่อสถานะเปลี่ยน
- ยังไม่มีการชำระเงินออนไลน์ (ค่าธรรมเนียมแสดงเป็นข้อมูลเท่านั้น)
- ยังไม่มีหน้าจัดการประเภทเอกสาร และการส่งออก CSV
- ยังไม่มี CAPTCHA หรือ rate limit บนฟอร์มสาธารณะ
- ยังไม่มีบทบาทเจ้าหน้าที่หลายระดับและ SLA
- การสมัครเจ้าหน้าที่ใช้รหัสลงทะเบียนร่วมกันหนึ่งรหัส ยังไม่มีขั้นตอนอนุมัติรายบุคคล ควรเปลี่ยนรหัสเมื่อมีคนลาออก และปิดรับสมัครเมื่อไม่ใช้

## Roadmap

1. แจ้งเตือนเมื่อสถานะเปลี่ยน (Supabase Edge Function + database webhook)
2. หน้าจัดการประเภทเอกสารและส่งออก CSV
3. ชำระเงินออนไลน์ (เช่น PromptPay QR) และใบเสร็จ
4. บทบาทเจ้าหน้าที่หลายระดับและ SLA
