# Document Request Portal (ระบบขอเอกสารออนไลน์)

เว็บพอร์ทัลน้ำหนักเบาสำหรับโรงเรียนและมหาวิทยาลัย ใช้จัดการคำร้องขอเอกสารทางการแบบออนไลน์:
**ยื่นคำร้อง → ตรวจสอบข้อมูล → ติดตามสถานะ → แจ้งเมื่อเอกสารพร้อมรับ**

ใช้ HTML + ES modules ล้วน ไม่ต้องติดตั้ง Node.js, npm และไม่มีขั้นตอน build ตั้งค่าได้ทั้งหมดผ่านเว็บเบราว์เซอร์

> ไฟล์นี้เป็นเอกสารหลักไฟล์เดียว รวมทั้งภาพรวม ข้อกำหนด MVP เทคโนโลยี วิธีติดตั้ง และวิธีแก้ไขโค้ด
> ส่วนโค้ดแยกเป็นไฟล์ย่อยตามหน้าที่ เพื่อให้แก้ไขหรือเพิ่มฟีเจอร์ได้ทีละจุด

## 1. ภาพรวมและเป้าหมาย

สถานะ: ร่าง MVP · ขอบเขต: ผู้ซื้อกลุ่มเดียว (งานทะเบียนของโรงเรียน/มหาวิทยาลัย) · เป้าหมาย: ทดลองตลาดกับลูกค้านำร่อง

งานทะเบียนรับคำขอใบรับรอง ใบแสดงผลการเรียน และเอกสารอื่น ๆ ผ่านแบบฟอร์มกระดาษ การมายื่นด้วยตัวเอง และการแชตถาม เจ้าหน้าที่ติดตามคำขอไม่ครบ และนักเรียนต้องถามซ้ำว่าเอกสารเสร็จหรือยัง

**เป้าหมายของ MVP:** ให้นักเรียนยื่นคำร้องพร้อมแนบไฟล์ได้ ให้เจ้าหน้าที่ทะเบียนดำเนินการได้ และให้นักเรียนติดตามสถานะออนไลน์ได้ ครบวงจรของคำร้องสำหรับผู้ซื้อกลุ่มเดียว

## 2. ผู้ใช้งาน

| บทบาท | การยืนยันตัวตน | รายละเอียด |
|---|---|---|
| ผู้ยื่นคำร้อง (นักเรียน/นักศึกษา) | ไม่ต้องล็อกอิน | ยื่นและติดตามคำร้องด้วยรหัสติดตามและรหัสนักเรียน |
| เจ้าหน้าที่ทะเบียน | อีเมล + รหัสผ่าน (Supabase Auth) และต้องอยู่ในตาราง `staff` | ตรวจสอบคำร้องและเปลี่ยนสถานะ |

## 3. Functional requirements

### ผู้ยื่นคำร้อง

| รหัส | ข้อกำหนด |
|---|---|
| FR-1 | เลือกประเภทเอกสารที่เปิดให้ขอ พร้อมแสดงค่าธรรมเนียม ระยะเวลา และเอกสารที่ต้องแนบ |
| FR-2 | กรอกชื่อ-นามสกุล รหัสนักเรียน (บังคับ) อีเมล เบอร์โทร วัตถุประสงค์ จำนวนฉบับ (1–20) และวิธีรับ (รับเอง/ไปรษณีย์ ถ้าเลือกไปรษณีย์ต้องกรอกที่อยู่) |
| FR-3 | แนบไฟล์ได้สูงสุด 5 ไฟล์ ชนิด PDF/JPG/PNG ไม่เกิน 5 MB ต่อไฟล์ |
| FR-4 | ได้รับรหัสติดตาม (รูปแบบ `DR-XXXXXXXX`) หลังยื่นสำเร็จ |
| FR-5 | ดูสถานะปัจจุบัน ข้อความจากเจ้าหน้าที่ และประวัติสถานะ โดยกรอกรหัสติดตาม **และ** รหัสนักเรียนให้ตรงกัน |

### เจ้าหน้าที่ทะเบียน

| รหัส | ข้อกำหนด |
|---|---|
| FR-6 | ล็อกอินและเห็นรายการคำร้องล่าสุด 200 รายการ |
| FR-7 | กรองตามสถานะ และค้นหาด้วยรหัสติดตาม รหัสนักเรียน หรือชื่อ |
| FR-8 | เปิดดูรายละเอียดคำร้องและดาวน์โหลดไฟล์แนบ |
| FR-9 | เปลี่ยนสถานะพร้อมฝากข้อความที่แสดงให้ผู้ยื่นเห็น |
| FR-10 | ระบบบันทึกประวัติสถานะอัตโนมัติทุกครั้งที่เปลี่ยนสถานะ |

### ค่าสถานะ

`submitted` (ยื่นแล้ว) → `reviewing` (กำลังตรวจสอบ) → `need_more_info` (ต้องแก้ไข/ส่งข้อมูลเพิ่ม) → `approved` (อนุมัติ) → `processing` (กำลังจัดทำ) → `ready` (พร้อมรับ/จัดส่ง) → `completed` (เสร็จสิ้น) และมี `rejected` (ไม่อนุมัติ) กับ `cancelled` (ยกเลิก)
เจ้าหน้าที่ตั้งสถานะใดก็ได้ ใน MVP ยังไม่บังคับลำดับขั้นตอน

## 4. Non-functional requirements

| รหัส | ข้อกำหนด |
|---|---|
| NFR-1 | หน้าเว็บใช้งานได้ทั้งมือถือและเดสก์ท็อป (responsive) |
| NFR-2 | เปิด Row Level Security ทุกตาราง ผู้ยื่นอ่านตาราง `requests` ตรง ๆ ไม่ได้ ใช้ได้เฉพาะฟังก์ชัน RPC (`submit_request`, `add_attachment`, `track_request`) |
| NFR-3 | ไฟล์แนบเก็บใน bucket แบบ private จำกัดชนิดและขนาดไฟล์ เจ้าหน้าที่เปิดผ่านลิงก์ชั่วคราวอายุ 2 นาที |
| NFR-4 | deploy ได้โดยไม่ต้อง build และไม่ต้องติดตั้งโปรแกรมในเครื่อง |
| NFR-5 | หน้าจอรองรับ 2 ภาษา (ไทย/อังกฤษ) สลับได้ทันทีโดยไม่โหลดหน้าใหม่ ค่าเริ่มต้นคือไทย และจำค่าที่เลือกไว้ในเบราว์เซอร์ |

## 5. โครงสร้างข้อมูล

| ตาราง | หน้าที่ |
|---|---|
| `request_types` | รายการประเภทเอกสาร: ชื่อ คำอธิบาย ค่าธรรมเนียม จำนวนวันดำเนินการ เอกสารที่ต้องแนบ (มีคอลัมน์ `_th` สำหรับข้อความภาษาไทย ถ้าไม่กรอกจะแสดงภาษาอังกฤษแทน) สถานะเปิด/ปิด |
| `requests` | คำร้องหนึ่งแถวต่อหนึ่งรายการ: ข้อมูลผู้ยื่น รหัสติดตาม สถานะ ข้อความจากเจ้าหน้าที่ เวลา |
| `attachments` | ข้อมูลไฟล์แนบที่ผูกกับคำร้อง (ตัวไฟล์อยู่ใน Supabase Storage) |
| `status_history` | บันทึกการเปลี่ยนสถานะแบบเพิ่มอย่างเดียว (เขียนโดย database trigger) |
| `staff` | ผู้ใช้ที่ได้รับสิทธิ์เป็นเจ้าหน้าที่ทะเบียน |

นิยามเต็ม (ตาราง นโยบาย RLS ฟังก์ชัน RPC storage และข้อมูลตัวอย่าง) อยู่ที่ `supabase/schema.sql`

## 6. เทคโนโลยี

| ด้าน | สิ่งที่ใช้ |
|---|---|
| ภาษา | HTML, CSS, JavaScript (ES modules), SQL (PostgreSQL / PL/pgSQL) |
| Framework | ไม่มี — JavaScript ล้วน (vanilla) ใช้ router แบบ hash และไม่มีเครื่องมือ build |
| ไลบรารี | `@supabase/supabase-js` v2 โหลดจาก CDN jsDelivr, ฟอนต์ Sarabun จาก Google Fonts |
| Backend | Supabase: PostgreSQL, Auth, Storage, Row Level Security, RPC functions |
| Hosting | Vercel (static) |
| Source control | GitHub |

## 7. โครงสร้างโปรเจกต์และวิธีแก้ไข/เพิ่มของใหม่

```
README.md               เอกสารหลักไฟล์นี้ (ภาพรวม + requirements + วิธีติดตั้ง)
index.html              โครงหน้าเว็บ (แถบเมนู + #app + จุดเริ่มต้นของโมดูล)
css/styles.css          สไตล์ทั้งหมด
js/config.js            ← ไฟล์เดียวที่ต้องแก้ตอนติดตั้ง (Supabase URL + anon key)
js/app.js               ตัวจัดการเส้นทางหน้า (hash router) และแถบเมนู/ปุ่มสลับภาษา
js/i18n.js              ข้อความภาษาไทย/อังกฤษทั้งหมด
js/lib/supabase.js      การเชื่อมต่อ Supabase (โหลดจาก CDN)
js/lib/utils.js         ฟังก์ชันที่ใช้ร่วมกัน ป้ายสถานะ ข้อจำกัดการอัปโหลด
js/pages/home.js        #/            หน้าแรก
js/pages/request.js     #/request     ยื่นคำร้อง + แนบไฟล์
js/pages/track.js       #/track       ติดตามสถานะสำหรับผู้ยื่น
js/pages/admin.js       #/admin       ล็อกอินและหน้าหลังบ้านเจ้าหน้าที่
supabase/schema.sql     ฐานข้อมูลทั้งหมด
vercel.json             header ความปลอดภัย
```

อยากแก้อะไร ให้ไปที่ไฟล์นี้:

| ต้องการ | แก้ที่ |
|---|---|
| เปลี่ยนคำ/ข้อความบนหน้าจอ หรือเพิ่มภาษา | `js/i18n.js` |
| เปลี่ยนสี หน้าตา ฟอนต์ | `css/styles.css` |
| แก้ฟอร์มยื่นคำร้อง | `js/pages/request.js` |
| แก้หน้าติดตามสถานะ | `js/pages/track.js` |
| แก้หน้าเจ้าหน้าที่ | `js/pages/admin.js` |
| เพิ่มหน้าใหม่ | สร้างไฟล์ใน `js/pages/` แล้วเพิ่มเส้นทางในตัวแปร `routes` ของ `js/app.js` และเพิ่มข้อความใน `js/i18n.js` |
| เพิ่มสถานะ | เพิ่มค่าใน enum `request_status` ใน `supabase/schema.sql`, เพิ่มรายการใน `STATUS_KEYS` ของ `js/lib/utils.js` และข้อความ `status.*` ใน `js/i18n.js` |
| เพิ่มคอลัมน์ข้อมูล | แก้ตารางและฟังก์ชัน RPC ใน `supabase/schema.sql` แล้วแก้หน้าที่เกี่ยวข้อง |
| เพิ่ม/แก้ประเภทเอกสาร | Supabase → Table Editor → `request_types` |

หลังแก้ไฟล์บน GitHub (กดรูปดินสอ แล้ว Commit) Vercel จะ deploy ใหม่ให้อัตโนมัติ

## 8. ขั้นตอนติดตั้ง (ทำผ่านเบราว์เซอร์ทั้งหมด)

### 8.1 Supabase
1. สร้างโปรเจกต์ที่ supabase.com
2. เปิด **SQL Editor** วางเนื้อหาจาก `supabase/schema.sql` แล้วกด **Run**
3. ไปที่ **Authentication → Users → Add user** สร้างบัญชีเจ้าหน้าที่ (ติ๊ก *Auto Confirm User*) แล้วคัดลอก UUID
4. ใน SQL Editor รัน:
   ```sql
   insert into staff (user_id, display_name) values ('<USER UUID>', 'Registrar Staff');
   ```
5. ไปที่ **Project Settings → API** คัดลอก **Project URL** และ **anon public key**

### 8.2 ตั้งค่า
แก้ไฟล์ `js/config.js`:

```js
export const SUPABASE_URL = "https://xxxx.supabase.co";
export const SUPABASE_ANON_KEY = "eyJ...";
```

anon key ออกแบบมาให้เปิดเผยได้ ความปลอดภัยมาจากนโยบาย Row Level Security ใน `supabase/schema.sql`
ห้ามใช้ `service_role` key ในโปรเจกต์นี้เด็ดขาด

### 8.3 GitHub
ที่ github.com เลือก **New repository** แล้วเลือก **uploading an existing file** ลากเนื้อหาในโฟลเดอร์โปรเจกต์ทั้งหมดเข้าไป (รักษาโครงสร้างโฟลเดอร์ไว้) แล้ว Commit

### 8.4 Vercel
ที่ vercel.com เลือก **Add New → Project** เลือก repo จาก GitHub ตั้ง **Framework Preset** เป็น **Other** (ไม่ต้องใส่ build command และ output directory) แล้ว Deploy
ทางลัด: ลากโฟลเดอร์โปรเจกต์ไปวางที่ vercel.com/new เพื่อ deploy โดยไม่ผ่าน GitHub

### 8.5 รันในเครื่อง (ไม่บังคับ)
ES modules โหลดจาก `file://` ไม่ได้ หากต้องการทดสอบในเครื่องให้เปิดเซิร์ฟเวอร์ เช่น `python3 -m http.server 8000` แล้วเข้า http://localhost:8000 ถ้า deploy ขึ้น Vercel ไม่ต้องทำขั้นตอนนี้

## 9. สิ่งที่ยังไม่อยู่ใน MVP

- แจ้งเตือนอีเมล/LINE เมื่อสถานะเปลี่ยน (ผู้ยื่นต้องเข้ามาดูหน้าติดตามเอง)
- ชำระเงินออนไลน์และใบเสร็จ (ค่าธรรมเนียมแสดงเป็นข้อมูลเท่านั้น)
- หน้าจัดการประเภทเอกสาร (ตอนนี้แก้ผ่าน Supabase Table Editor)
- CAPTCHA และ rate limit บนฟอร์มสาธารณะ
- ส่งออก CSV และรายงาน
- หลายบทบาทเจ้าหน้าที่ ขั้นตอนอนุมัติ และ SLA
- ภาษาที่สาม (เพิ่มได้โดยเพิ่มข้อความใน `js/i18n.js`)
- ข้อความจากฐานข้อมูลที่ไม่ได้ทำสองภาษา (ข้อความ error ที่ระบบไม่รู้จัก และข้อความที่เจ้าหน้าที่พิมพ์เอง) จะแสดงตามที่บันทึกไว้

## 10. เกณฑ์ว่าผ่าน MVP

1. นักเรียนยื่นคำร้องพร้อมไฟล์แนบอย่างน้อย 1 ไฟล์ได้ และได้รับรหัสติดตาม
2. เจ้าหน้าที่ล็อกอิน หาคำร้องเจอ เปิดไฟล์แนบ และเปลี่ยนสถานะพร้อมข้อความได้
3. นักเรียนเห็นสถานะใหม่ ข้อความ และประวัติสถานะในหน้าติดตาม
4. ใส่รหัสนักเรียนผิดกับรหัสติดตามที่ถูก ระบบตอบว่า "ไม่พบ" และไม่เปิดเผยข้อมูลใด ๆ
5. ผู้ใช้ที่ล็อกอินแต่ไม่ใช่เจ้าหน้าที่ อ่านคำร้องหรือไฟล์แนบไม่ได้

## 11. ความเสี่ยงและประเด็นที่ยังเปิดอยู่

- ยังไม่ได้ทดสอบกับโปรเจกต์ Supabase จริง หลังตั้งค่าควรทดสอบ flow ทั้งหมดหนึ่งรอบ
- จุดรับคำร้องสาธารณะยังไม่มีการป้องกันการใช้งานผิดปกติ (เสี่ยงสแปม)
- ยังไม่ยืนยันความต้องการของตลาด ควรยืนยันว่าลูกค้านำร่องยินดีจ่ายก่อนพัฒนาต่อ

## 12. แผนพัฒนาต่อ

1. แจ้งเตือนเมื่อสถานะเปลี่ยน (Supabase Edge Function + database webhook)
2. หน้าจัดการประเภทเอกสารและส่งออก CSV
3. ชำระเงินออนไลน์ (เช่น PromptPay QR) และใบเสร็จ
4. บทบาทเจ้าหน้าที่หลายระดับ (ทะเบียน / ผู้อนุมัติ) และ SLA
